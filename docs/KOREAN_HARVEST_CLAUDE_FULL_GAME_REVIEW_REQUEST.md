1. 게임 진행과 잠금 해제 로직
2. 퍼즐 입력, 힌트, 다음 그림, 키패드 조작
3. 팬트리 수집품 구매·전시·추가 스푼 확률

6. 배경음악·효과음·앱 생명주기 처리
7. 로컬 저장 데이터의 마이그레이션과 경제 안전성
8. 한국어·영어 기능 및 문구 동등성

10. 강제 업데이트 정책과 양대 스토어 배포 순서
11. Android AAB와 iOS IPA의 버전·서명·동일 소스 여부
12. 회귀, 접근성, 성능, 유지보수 위험

## 2. 결과 작성 형식

결과는 다음 순서로 작성해 주세요.

### A. Findings

실제 문제만 `P0`부터 `P3`까지 위험도 순으로 작성합니다.

- `P0`: 데이터 손실, 결제 오류, 모든 기존 사용자의 실행 차단, 잘못된 강제 업데이트 등 즉시 출시 중단 사유
- `P1`: 주요 진행 불가, 잠금 우회, 경제 악용, 핵심 화면 파손, 양대 플랫폼 기능 불일치
- `P2`: 명확한 UX 회귀, 잘못된 안내, 특정 화면 크기의 조작 불편, 사운드 수명주기 문제
- `P3`: 사소한 시각 불일치, 문구 개선, 낮은 위험의 유지보수 문제

각 finding에는 반드시 다음을 포함해 주세요.

- 정확한 파일 경로와 줄 번호
- 재현 조건 또는 입력 상태
- 사용자에게 보이는 결과
- 출시 위험
- 가장 작은 안전한 수정 방향
- 수정 후 필요한 회귀 테스트

근거 없는 추측이나 취향 차이는 finding으로 만들지 마세요. 문제가 없다면 Findings에 `No actionable findings`라고 명시해 주세요.

### B. 기능별 검토표

각 영역을 `PASS`, `PASS WITH NOTE`, `FAIL`, `NOT VERIFIED` 중 하나로 판정해 주세요.

### C. 출시 판정

마지막 줄은 아래 셋 중 하나만 사용해 주세요.

- `BLOCKED`
- `READY FOR FIXES THEN RECHECK`
- `READY TO SHIP`

### 3.3 강제 업데이트

## 4. 방금 추가한 진행 유도 로직 — 집중 검토

이번 마지막 수정에서 사용자 진행 경로를 크게 정리했습니다. 아래는 반드시 코드와 실제 상태 전이 양쪽에서 확인해 주세요.

### 4.1 `지금 풀기` 계약

`지금 풀기`는 다음 우선순위를 따라야 합니다.

1. 가장 최근에 완료한 퍼즐의 다음 퍼즐
2. 이후 구간에 미완료이면서 현재 열려 있는 퍼즐
3. 끝까지 갔다면 앞에서 놓친 미완료 퍼즐
4. 열려 있는 퍼즐을 모두 완료했고 다음 스테이지가 팬트리 조건으로 잠겨 있다면 팬트리 안내
5. 정말 모든 콘텐츠를 완료한 경우에만 전체 완료 상태

새 플레이어는 첫 퍼즐부터 시작해야 하며 두 번째 퍼즐로 건너뛰면 안 됩니다. 잠긴 스테이지의 퍼즐을 직접 열어서도 안 됩니다.

### 4.2 `다음 그림` 계약

- 완료 화면에서 `다음 그림`을 누르면 현재 퍼즐 다음의 미완료·접근 가능 퍼즐을 찾아야 합니다.
- 중간에 이미 풀어 둔 퍼즐은 건너뜁니다.
- 뒤에 풀 퍼즐이 없지만 앞에 놓친 퍼즐이 있으면 그 퍼즐로 돌아갑니다.
- 놓친 퍼즐도 없고 다음 스테이지가 팬트리 때문에 잠겨 있으면 퍼즐을 무한 순환시키지 말고 팬트리 안내를 띄웁니다.
- 빠른 연속 탭으로 두세 단계가 건너뛰거나 중복 화면이 열리면 안 됩니다.

### 4.3 스테이지 완료 후 팬트리 유도

- 한 스테이지의 퍼즐을 모두 풀었지만 다음 스테이지의 팬트리 조건을 충족하지 않았다면 아래 내용이 명확하게 보여야 합니다.
  - 현재 스테이지의 그림을 모두 완성했다는 사실
  - 다음 스테이지를 열려면 연결된 팬트리 선반을 완성해야 한다는 사실
  - 지금 팬트리로 이동한다는 행동
- 안내에는 목적이 다른 우회 버튼이 없어야 합니다.
- `팬트리 선반 채우러 가기` 단일 버튼을 누르면 실제 팬트리 화면으로 이동해야 합니다.
- 이동한 팬트리의 첫 잠금 해제 대상과 설명이 사용자가 이해할 수 있어야 합니다.

### 4.4 불필요한 이웃 캐릭터 대화 제거

- 팬트리를 둘러볼 때 특별한 기능 안내 없이 등장하던 Lily와 Mateo 대화는 제거되었습니다.
- 해당 이미지 import, 대화 키, 가이드 ID, 표시 조건이 남아서 다시 등장하지 않는지 확인해 주세요.
- 기존 저장에 과거 가이드 ID가 남아 있어도 오류가 발생하면 안 됩니다.
- Mr Park는 타임어택에 기능적 목적이 있으므로 무조건 제거 대상이 아닙니다.
- 팬트리에서는 핍이 현재 기능인 `홈 화면에 전시`와 추가 스푼 확률을 설명하는 흐름만 유지되어야 합니다.

## 5. 팬트리와 추가 스푼 확률

현재 제품 방향은 다음과 같습니다.

- 수집품의 별도 `효과 활성화` 기능은 삭제되었습니다.
- `수집품 선택하기`처럼 기능이 불분명한 별도 선택도 없어야 합니다.
- 홈 화면에 표시한 수집품이 현재 전시품이며 추가 스푼 확률의 기준입니다.
- 팬트리 선반 완성과 현재 전시 상태가 서로 모순되면 안 됩니다.
- 홈 화면의 전시 수집품을 누르면 추가 스푼 획득 확률 설명을 다시 볼 수 있어야 합니다.
- 긍정적인 확률은 `5%`가 아니라 `+5%`처럼 보너스임을 분명히 표시합니다.
- 0%를 `보너스 확률 0%`처럼 좋은 효과로 오해하게 표현하면 안 됩니다. 아직 잠겼거나 성장 조건이 남았다는 의미로 보여야 합니다.
- 구매할 스푼이 부족한 경우 단독 버튼이 어색하게 떠 있지 않고 상세창의 행동 구조가 자연스러워야 합니다.
- 수집품 구매·전시 변경·추가 스푼 판정으로 스푼이 중복 지급되거나 음수가 되면 안 됩니다.

## 6. 키패드, 터치 및 퍼즐 플레이

### 6.1 키패드 연속 칠하기

- 방향키를 가볍게 한 번 누르면 커서만 이동해야 합니다.
- 칠하기 버튼이 선택되어 있다는 이유만으로 모든 방향키 이동에 칠하기가 적용되면 안 됩니다.
- 연속 칠하기는 의도적인 길게 누르기 이후에만 시작해야 합니다.
- 길게 누르기 시작과 종료가 분명해야 하며 손을 뗀 뒤 추가 칸이 칠해지면 안 됩니다.
- 채우기와 X 표시 모두 같은 안전 규칙을 따라야 합니다.
- 보드 경계를 넘거나 빠르게 방향을 바꿀 때 중복 입력이 없어야 합니다.
- 10×10과 12×12에서 조작부가 보드, 숫자 힌트, 하단 진행 표시를 가리지 않아야 합니다.

### 6.2 직접 누르기와 설정

- 설정의 조작 방식 명칭과 실제 퍼즐 화면의 명칭이 일치해야 합니다.
- `칸 직접 누르기`와 `방향키 사용`이 사용자가 이해할 수 있게 구분되어야 합니다.
- 설정 변경이 iOS와 Android 양쪽에서 동일하게 저장되어야 합니다.

### 6.3 퍼즐 핵심 안전성

- 셀 채우기, X 표시, 되돌리기, 힌트 사용, 완성 판정이 일관되어야 합니다.

- 앱을 백그라운드로 보냈다가 돌아와도 퍼즐 상태가 손실되면 안 됩니다.

- 보유한 일반 수집품과 해금한 추석 소품을 홈에 함께 전시하면 기존 팬트리 성장 확률에 **+2%p**를 더합니다. 한쪽만 전시하거나 잠긴 소품을 저장 데이터로 지정한 경우에는 발동하지 않습니다.
- 기존 팬트리 확률 곡선과 일반 수집품 효과는 변경하지 않았으며, 최대 합산 확률은 기존 26% + 추석 2% = 28%입니다.
- 홈에서는 일반 수집품에 합산 확률, 추석 소품에 `+2%` 보조 배지를 각각 표시합니다. 팬트리 추석 선반에도 두 아이템을 함께 전시해야 한다는 규칙과 활성 상태를 표시합니다.
- 실제 퍼즐 완료 보너스 추첨도 화면 표시와 동일한 합산 확률을 사용합니다.
- 자동 모바일 QA가 일반 수집품·추석 소품·배지의 공존, 동일 선반 배치, 비겹침, 일반 `+7%` 및 추석 `+2%` 배지를 4개 해상도에서 검증하도록 보강했습니다.
- 재검증: 72 files / 445 tests, Android/iOS 릴리스 게이트, 모바일 360×740·390×844·430×932·675×900, 최종 `qa:candidate`, `git diff --check` 모두 통과했습니다.
